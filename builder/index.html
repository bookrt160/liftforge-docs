    Elevator Builder¶

    The Elevator Builder is an editor tab that creates elevators from presets and lets you override anything. Open it from Tools > LiftForge > Elevator Builder. The tab is called LiftForge Builder.

    Create a car¶

    1. Pick a preset in the builder.
    2. Choose Create. A new elevator actor is placed in the level and built from the preset. Undo removes it.

    Edit an existing car¶

    1. Select an elevator actor in the level.
    2. Choose Use selected to load it into the builder.
    3. Enable Configuration Override on the actor (bUseConfigurationOverride). Without it the car follows its preset, and your edits to Configuration are ignored.
    4. Edit the Configuration in the Details panel (see below).
    5. Choose Rebuild to regenerate the geometry. A rebuild keeps your overrides and any components you added yourself. Only generated parts are regenerated.

    Preview doors opens or closes the doors in the editor so you can check the opening without playing. Validate checks the configuration and lists any problems.

    What you can configure¶

    All of these are properties of the configuration (FLFElevatorConfiguration). Lengths are in centimetres, speeds in cm/s.

    Group Properties
    Identity Display name, Type (Passenger, Freight, Panoramic, Hydraulic, Platform, Cycle), Drive (gearless, geared, hydraulic), Door layout (centre opening, side sliding, telescopic, hinged)
    Floors Id, label, elevation, front and rear entrance, access level, announcement, for each landing. List floors from lowest to highest.
    Car and door size Cabin width, depth, height; door width and height
    Motion Max speed, max acceleration, max jerk
    Timing Door seconds, dwell seconds
    Load Capacity (kg), mass counted per pawn
    Dispatch Starvation seconds, direction change penalty seconds
    Look Visual set, or the four kit materials (cabin, door, floor, machinery); detail draw distance
    Sound Volume and one slot per sound; see Presets and visual sets
    Brand line Optional text printed on the car panel. Empty prints nothing.

    Per actor you can also set ElevatorId, BankName / DispatchBank, Shaft Collision, Static Fixed Parts, and the inspection options. Details: API reference (ALFElevator).

    Rules the builder checks¶

    Validate rejects a configuration (and an invalid car does not operate) when, for example:

    • there are no floors, or more than 128;
    • floor elevations are not sorted or are duplicated;
    • there are more floor buttons than fit beside the door (the panel grid grows for tall buildings, up to a limit);
    • imported parts are missing or malformed.

    In the editor the problems go to the Message Log (Map Check) once per distinct problem, and an invalid actor shows a placeholder box with text instead of disappearing.

    When you add a row to Floors, the new row is empty, so the car is invalid until you fill in its Id, Label and Elevation: until then you see a Message Log warning, the placeholder box and the text "Invalid LiftForge configuration". This is expected.

    Displays¶

    The cabin display, the panel display and the landing displays show the floor Label. When the car is parked they show the floor it stands at. While it moves they show the floor it is passing (it changes half way between two floors) with the direction (UP / DN, or arrows when the display font has them), then the arrival floor. A car stopped between floors shows the nearest floor. Network clients show the same.

    Changing a car while playing¶

    You can change Preset, Configuration or ImportedParts at runtime. Then call Rebuild Assembly (geometry) or Mark Configuration Dirty (validation only). A preset swap or a changed floor count is also detected on the next tick. Calls to floors that no longer exist are dropped, and the car finds its landing again by floor id. A rebuild requested while the car moves runs when it arrives. The cabin floor component is kept, so riders stay on it.

    Large buildings¶

    Two to 128 floors are supported (one floor, or more than 128, is rejected with a message and the car does not operate). Cars with many floors get a fitted button grid beside the door. How many buttons fit depends on the cabin: a 220 cm wide cabin takes 40 floors, but a narrow ISO-sized cabin (135 cm wide with a 90 cm door) does not take 30. The validation message then says to widen the cabin, narrow the door or serve fewer floors. For tall buildings the instanced fixed parts keep the draw cost down; see Performance tips.

    Imported assemblies (advanced)¶

    ImportedParts lets you fit your own meshes instead of the generated kit: each part (FLFImportedPart) has a role (ELFImportedPartRole: CabinFloor, CabinRigid, CabinDoor, LandingFixed, LandingDoor, ShaftFixed), a transform, a floor id for landing roles and a collision flag. Validation requires centre-opening doors, unique part names, loadable meshes, exactly one colliding cabin floor and both colliding door leaves for every served entrance. After changing it from gameplay code, call Mark Configuration Dirty or Rebuild Assembly.
